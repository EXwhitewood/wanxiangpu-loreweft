# 架构概览 / Architecture Overview

万象谱由三个本地层次组成：

1. `frontend/`：React/TypeScript 创作界面；
2. `backend/`：FastAPI 服务、SQLite 持久化、工作流与 AI 编排；
3. `src-tauri/`：Windows 桌面宿主、内置后端生命周期、数据目录和 Updater。

## 核心数据流

```text
用户操作
  -> React 前端
  -> 本地 FastAPI (127.0.0.1)
  -> SQLite / 本地创作数据目录
  -> 用户配置的模型 API（仅在执行相应 AI 功能时）
```

桌面发行版会启动内置 Python 后端，监听回环地址上的可用端口。浏览器开发模式默认使用 `8000`，桌面端优先使用 `18000` 并在冲突时选择受控回退端口。

## 两条写作路线

- AI 自动写作：大纲 → 章节蓝图 → 生成 → 审查/修复 → 提交 → 状态推进；
- 用户辅助写作：用户手写 → 保存正文 → 异步状态结算 → 质量诊断 → 用户决定修复、忽略或修改大纲。

两条路线共享事实、世界观和章节状态，但用户正文持久化不依赖附属结算成功，AI 普通生成也不得静默覆盖已有用户正文。

## 状态与恢复

- SQLite 是创作状态的权威持久层；
- 派生状态通过可重放作业和 outbox 保持幂等；
- 用户正文先以短事务落库，摘要、诊断、世界观和叙事状态在后台分阶段结算；
- 项目归档用于跨设备备份和恢复，不把 Markdown/Word 阅读导出冒充完整备份。

## Runtime Skills

`backend/app/agent_skills/` 中的 Skill、参考资料和资源属于程序运行所需内容，会随源码和桌面安装包一同提供。私人读者语料和用户创作数据不进入源码仓库或 Release；相关测试必须使用合成数据和隔离的临时目录。
